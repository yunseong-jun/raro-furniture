- 상태: 사용자 승인 완료 (brainstorming 단계에서 방향 B, 메인 구성, 서브 페이지 구성 모두 승인)
- 프로젝트 폴더: `c:/Users/전윤성/yunseong/raro-furniture/`

## 1. 목표와 배경

현재 사이트는 고도몰(NHN커머스) 기본 스킨 "mplshop" 위에 운영 중이며, 섹션이 12개로 많고 중복(BEST/HIT, 추천상품/히어로), 플레이스홀더(유튜브 섹션, HISTORY 페이지), 좌측 퀵메뉴 등 불필요한 요소가 많다. 상품 상세는 "상세페이지 참조"로 채워진 표와 긴 이미지뿐이다.

목표는 **Article(article.com)과 Floyd(floydhome.com)를 참조한 "가구 브랜드다운" UI**로 사이트를 다시 설계하되, **나중에 고도몰 스킨에 그대로 옮길 수 있는 구조**로 만드는 것이다. 사용자는 현재 관리자 권한이 없으므로 이번 결과물은 독립 실행되는 정적 프로토타입이다.

## 2. 범위

### 1단계 (이번 구현) — 핵심 4페이지

### 범위 밖
- 실제 결제·로그인·장바구니 동작 (링크와 UI만)
- 고도몰 관리자 반영 (권한 없음). 대신 이식 가이드 문서를 제공한다.
- 참조 사이트의 로고·사진·문구 복제 (레이아웃·색·타이포 패턴만 참조)

## 3. 디자인 방향 (승인: B "화이트 쇼룸", Article 60 : Floyd 40)

### 3.1 원칙
1. 흰 바탕 + 큰 사진 + 굵은 문장형 헤드라인(마침표로 끝남) — Article
2. 알약(pill) 버튼, "공간별로 둘러보기" 썸네일 행, 연회색 상품 타일 — Article
3. 작은 대문자 라벨(예: `BRAND STORY`), 크림색 브랜드 띠, 50/50 분할 피처, 넉넉한 세로 여백 — Floyd
4. 그림자 없음, 보더 최소, 여백으로 구획
5. 액센트 색은 테라코타 1색만, 세일·할인율·구독 버튼에만 사용
6. **로고는 원본 PNG 그대로 사용** (헤더 높이 30px, 다크 푸터에서는 CSS `filter`로 흰색 반전). 파일: `assets/logo-header.png` (320×60)

### 3.3 타이포그래피
- 서체: Pretendard (jsdelivr CDN, `pretendard.min.css`). 라벨용 모노: `JetBrains Mono` (Google Fonts) — 라벨에만.
- 스케일: 히어로 H1 44px/700, 섹션 H2 28px/700, 카드 제목 15px/600, 본문 15px/400, 상품명 14px, 가격 15px/700, 캡션 12px, 라벨 11px 대문자 자간 0.12em.
- 행간: 헤드라인 1.2, 본문 1.6.
- 모바일: H1 30px, H2 22px.

### 3.4 공통 컴포넌트
- **헤더**: 1행 = 로고(좌) · 검색창(중앙, 알약형) · 로그인/찜/장바구니(우). 2행 = 대분류 5개 | BEST · NEW · SALE | 브랜드 · 쇼룸 · 리뷰. 대분류 호버 시 소분류 드롭다운. 모바일: 로고 + 검색 아이콘 + 햄버거, 전체 메뉴는 슬라이드 패널. 스크롤 시 헤더 축소 고정.
- **상품 카드**: 1:1 타일(`--tile` 배경, 이미지 `object-fit: cover`), 좌상단 뱃지(특가/NEW 텍스트 1종), 우상단 하트, 상품명 2줄 말줄임, 가격 행(할인율 `--accent` + 판매가 굵게 + 정가 취소선), 캡션(별점·리뷰 수·무료배송).
- **버튼**: primary(먹색 배경/흰 글자), secondary(흰 배경/먹색 보더), 모두 알약형, 높이 44px(모바일 48px), 대문자 아님.
- **섹션 헤더**: 라벨(선택) + H2 + 보조 문장 + 우측 "전체 보기" 링크.
- **푸터**: 다크. 5열(회사 정보 / 고객센터 / 쇼핑 안내 / 회사 / 뉴스레터). 로고 흰색 반전. 사업자 정보는 현재 사이트 값 그대로.
- **모바일 하단 채팅 버튼** 1개(카카오톡 상담 링크). 기존 퀵메뉴·네이버톡톡 플로팅은 제거.

## 4. 페이지 설계

### 4.1 메인 (`index.html`) — 9개 블록 (승인)
1. **헤더** (공통)
2. **히어로**: 풀블리드 사진 1~2장(슬라이드), 중앙 정렬 헤드라인 + 보조 문장 + 흰 알약 버튼. 상단 그라데이션으로 글자 가독성 확보. 자동 전환 6초, 점 인디케이터.
3. **공간별로 둘러보기**: 대분류 5개(세라믹·대리석 식탁, 원목 식탁, 거실가구, 의자, 서재·침실)를 4:3 썸네일 + 캡션으로. 모바일은 가로 스크롤.
4. **이번 주 특가**(기존 Weekly HOT 10): 가로 스크롤 카드 10개, "7일 단독 최저가" 라벨, 남은 기간 표기(정적 텍스트), 할인율 뱃지.
5. **이번 달 베스트**(BEST + HIT PRODUCT 통합): 4열 × 2행 = 8개.
6. **브랜드 띠**(크림): 라벨 `BRAND STORY` + "현대적 감각으로 자연을 다듬다." + 2줄 요약 + 버튼 2개(브랜드 스토리 / 일산 쇼룸 안내) | 우측 공방 사진.
7. **새로 나온 가구**(NEW + CHOICE 통합): 탭 칩(전체/식탁/소파/의자/침실·서재) → 4열 그리드 8개. 탭 전환은 JS 필터.
8. **고객의 공간에서**(PHOTO ALBUM + REVIEW 통합): 좌측 큰 룩북 사진 1 + 우측 후기 사진 카드 2(별점·발췌·이름 마스킹).
9. **푸터** (공통)

제거: 공지 티커, 즐겨찾기 아이콘, 회원가입 포인트 띠, 좌측 퀵메뉴(작은 로고·공지 롤링·배송조회·택배사 링크), HIT PRODUCT, 이달의 추천상품 배너, Youtube_Movie, INSTAGRAM, 비밀번호 인증 팝업, 인트로 팝업, 중복 메뉴, 알록달록한 아이콘 뱃지.

### 4.2 상품 목록 (`list.html?cate=<코드>`) — 3개 블록 (승인)
1. **카테고리 헤더**: 브레드크럼 › 제목(대분류 또는 소분류) › 한 줄 설명(카테고리별 고정 문구, 데이터 JSON에 보관) › 소분류 칩(전체 N + 소분류들, 선택 시 필터).
2. **필터 + 그리드**:
   - 데스크톱: 좌측 150px 고정(sticky) 필터. 그룹: 사이즈(800 이하·1200–1400·1600–1900), 형태(사각·원형·타원), 상판/소재(카테고리별 다름), 구성(세트·단품), 가격(3구간). 체크박스, 적용 즉시 반영, 선택된 필터는 상단에 칩으로 표시(✕로 해제).
   - 필터 값은 **상품명에서 규칙으로 추출**(숫자 → 사이즈, "원형/타원" → 형태, "유광/무광/대리석/원목" → 상판, "단품/세트" → 구성). 추출 규칙은 `data/build.py`에 둔다.
   - 우측: 개수 + 정렬(추천·판매인기·낮은가격·높은가격·상품평·최신). 3열 그리드(데스크톱), 2열(모바일). 12개씩 "더 보기".
   - 모바일: 필터 버튼 → 하단 시트.
3. **구매 가이드 띠**(크림): 카테고리별 1개 문구 + 다이어그램 자리(1단계는 텍스트 도식).

### 4.3 상품 상세 (`view.html?no=<goodsNo>`) — 6개 블록 (승인)
1. **갤러리 + 구매 패널**: 7:5 2단. 갤러리 = 큰 이미지 + 썸네일 6개(클릭 전환, 좌우 화살표). 패널(`position: sticky; top: 헤더 높이`) = 라벨(소분류·시리즈) › 상품명 › 별점·리뷰·Q&A 수 › 가격 행 › 배송비 문구 › **구성 선택 카드형 라디오**(기본 구성 가격, 나머지는 ±차액) › 색상 스와치(옵션 있을 때만) › 수량 › 총액 › 버튼(장바구니 / 바로 구매 / ♡) › 안내 3줄(쇼룸 실물 확인·상담 전화·교환 반품).
2. **탭 바**(스크롤 시 헤더 아래 고정): 상세정보 · 사양·치수 · 배송·교환·반품 · 리뷰 N · Q&A N. 클릭 시 해당 섹션으로 스크롤.
3. **핵심 특징 3개**: 사진 + 제목 + 1~2문장. 데이터 JSON의 `features` 배열(없으면 카테고리 기본값).
4. **사양·치수**: 도면 자리 + 표(상판·프레임·치수·제조·KC·AS·보증). 값이 없으면 "상세 이미지 참조"가 아니라 항목 자체를 숨긴다.
5. **상세 이미지**: 기존 상세 이미지 URL들을 세로로 이어 붙임, 기본 접힘(높이 800px) + "펼쳐 보기".
6. **리뷰 요약 + 함께 보기**: 평균 별점·분포 막대 + 사진 후기 4칸(1단계는 자리) → 같은 시리즈 상품 4개 + 비슷한 상품 4개(같은 소분류에서 가격 근접순).
- 모바일: 하단 고정 바(총액 + 구매하기), 패널은 갤러리 아래로.

## 5. 데이터

### 5.1 수집 (`data/build.py`)
- 소스: 현재 사이트 HTML을 `curl`과 같은 방식(브라우저 UA)으로 직접 요청. robots.txt가 봇을 차단하므로 Firecrawl은 쓰지 않으며, 요청은 대분류 5개 목록 + 상품 상세 약 12개 + 메인 1개 = **20건 안팎**으로 제한하고 요청 간 1초 대기.
- 목록에서: goodsNo, 상품명, 썸네일 URL, 판매가, (있으면) 정가, 아이콘 종류(무료배송 등), 카테고리 코드.
- 상세에서(대표 상품만): 정가·판매가, 배송비 문구, 옵션(구성 선택 목록), 갤러리 이미지(`_1000_N.jpg`), 상세 이미지 URL 목록, 상품정보고시 표.
- 이미지는 다운로드하지 않고 원본 URL을 그대로 쓴다(hgodo 서버는 외부 참조 허용 확인됨). 로고와 회사소개 배너만 `assets/`에 보관.

- 상세를 수집하지 않은 상품은 `gallery`가 썸네일 1장, `options`가 빈 배열이다. 상세 페이지는 이 경우 옵션 블록을 숨기고 "구성 문의"로 대체한다.
- `desc`, `guide`, `features`처럼 사이트에 없는 문구는 이 문서의 4장에 맞춰 **직접 작성**하되, 사실(치수·소재)은 상품명·상세 표에서 확인된 것만 쓴다. 확인 안 되는 값은 "확인 필요"로 표시한다.

### 5.3 렌더링
- 각 HTML은 정적 마크업(헤더·푸터·섹션 틀)을 갖고, 상품 카드·옵션·필터 같은 반복 요소만 `assets/app.js`가 `site.json`을 `fetch`해 렌더링한다.
- `file://`로 열면 `fetch`가 막히므로 로컬 정적 서버(`python -m http.server`)로 확인한다. README에 명시.
- JSON 로드 실패 시: 섹션 자리에 "상품을 불러오지 못했습니다" 문구, 페이지 나머지는 정상 표시.
- 이미지 로드 실패 시: 타일 배경만 남고 `alt` 텍스트 표시(`onerror`로 placeholder 클래스).

## 8. 검증
- **시각 확인**: `python -m http.server 8080` 후 Edge 헤드리스(`msedge --headless --screenshot --window-size=W,H`)로 1440·1024·390 폭 스크린샷을 페이지 4개 × 3폭 = 12장 찍어 직접 확인. 결과는 `docs/screenshots/`에 저장.
- **동작 확인**: 필터·정렬·탭·갤러리·옵션 총액 계산은 `app.js`의 순수 함수로 분리하고 `tests/app.test.html`(브라우저에서 여는 간단한 assert 페이지)로 확인.
- **콘텐츠 확인**: `site.json`의 상품 수·카테고리 수·가격 누락 여부를 `build.py` 마지막에 요약 출력.
- **사용자 확인**: 위 URL을 브라우저에서 열어 4페이지를 검토. 이 시점이 1단계 완료 게이트이며, 승인 후 2단계 계획을 세운다.
